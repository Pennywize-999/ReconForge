# ReconForge Architecture

ReconForge v0.2.0 utilizes a modular, decoupled architecture that strictly separates target planning from offline analysis and reporting.

## Core Pipeline

1. **CLI (`reconforge/cli.py`)**: Entry point handling argument parsing and interactive prompting.
2. **Target Normalization**: Parses and breaks down URLs/IPs into standardized models (`ReconTarget`), preserving scheme, host, IP, and port structures.
3. **ReconPlanner**: Selects applicable tools from the Tool Registry based on the normalized target properties and execution mode.
4. **Tool Registry**: Maintains tool definitions, adapters, and compatibility rules.
5. **ExecutionBackend**: Handles tool execution logic. Currently implemented strictly as a `PlanningOnlyBackend`.
6. **Parsers / Analyzers**: Extracts data from external tool outputs.
7. **Correlation**: Links related findings (e.g., associating a web directory discovered by Gobuster to the HTTP service on port 80 found by Nmap).
8. **Reports**: Formats the correlated intelligence into human/machine-readable outputs.

## Distinction of Components

- **Planning**: The process of determining *which* tools to run and *how* to run them (e.g., passing specific flags based on `--mode low-impact`).
- **Execution Backend**: The subsystem that would normally run the planned commands via subprocesses.
- **Offline Parsing**: Ingesting files (like `.xml` or `.txt`) generated by external tools.
- **Analysis**: Transforming parsed data into intelligence (e.g., scoring confidence, mapping CPEs, detecting WAFs).
- **Reporting**: Generating the final output payload (Terminal, JSON, HTML).

## PlanningOnlyBackend

The current release (v0.2.0) enforces a `PlanningOnlyBackend`.
**Why it exists:** ReconForge is designed as a reconnaissance *analyzer*. To ensure safe operation and prevent unauthorized active scanning, the current backend intercepts execution plans, simulates success, and stops before any network traffic is generated.
**What it does:** It prints the planned commands and arguments to the user, proving the planner logic is correct without making network requests. No active backend currently exists.

## Tool Registry

The Tool Registry (`reconforge/tools/`) manages:
- **Tool Definitions & Adapters**: Code that knows how to construct command-line arguments for specific tools (e.g., `NmapAdapter`).
- **Target Compatibility**: Determining if a tool can run against a specific target (e.g., Gobuster only runs if HTTP/HTTPS is detected).
- **Availability Checks**: Validating if the tool binary is present in the `PATH`.
- **Output/Parser Relationships**: Mapping a tool's output format to the correct Parser module.

**Currently Implemented Adapters:**
- Nmap
- Gobuster

**Adding Future Adapters:**
A future adapter can be added simply by creating a new class extending `BaseAdapter` in `reconforge/tools/adapters/` and registering it. The analyzer remains completely decoupled from the tool because data ingestion happens via generic Parsers, not the Adapter.

## Parsers

Parsers (`reconforge/parsers/`) extract intelligence from raw outputs. Currently implemented and supported formats:
- Nmap XML
- DNS
- HTTP (Headers)
- SMB
- TLS
- Web/Dirb/Gobuster style output
- WhatWeb
- Generic text

## Vulnerability Intelligence

The core vulnerability engine (`reconforge/core/cpe.py`, `reconforge/core/vuln.py`, `reconforge/core/analyzer.py`) maps discovered services to known vulnerabilities.
- **CPE Extraction**: Derives Common Platform Enumeration strings from banners and service versions.
- **CVE Evidence & Severity**: Attaches CVE IDs and maps CVSS severities.
- **Confidence & Deduplication**: Scores findings based on evidence quality and deduplicates overlapping reports.
- **Correlation**: Cross-references offline intelligence to build a cohesive threat profile.
*(Note: ReconForge v0.2.0 does not perform live external CVE database lookups; it relies on offline heuristic matching and evidence analysis.)*

## WAF Analysis

The WAF subsystem (`reconforge/web/waf/`) provides conservative, low-impact analysis.
- **WAF Detection & Evidence**: Parses HTTP headers (`Server`, `Via`, `X-CDN`) to identify WAFs/CDNs.
- **Rate-Limit Indicators**: Extracts `Retry-After` metrics to warn the user of potential blocks.
- **Low-Impact Analysis**: Adjusts confidence scoring when WAF interference is suspected.
*(Note: This is strictly an analysis tool, not a WAF evasion or bypass system.)*

## Reporting

Reporters format the session intelligence.
- **Terminal**: `reconforge report <id> --format terminal` (Pretty-printed ASCII output)
- **JSON**: `reconforge report <id> --format json` (Structured data)
- **HTML**: `reconforge report <id> --format html` (Interactive offline dashboard)

Reports are generated dynamically from the underlying session state whenever a user runs the `reconforge report` command.

## Sessions

Sessions manage the state of analyzed targets.
- **Session Storage**: Sessions are stored locally as JSON files inside the `~/.reconforge/sessions/` directory.
- **Listing Sessions**: `reconforge sessions` reads this directory.
- **Current/Latest Session**: Using the identifier `current` instructs ReconForge to resolve the most recently modified session JSON file.
- **Report Generation**: Reports are hydrated entirely from these localized session files.
